# L1-E — OEB / Product-System Specialization and Precedence

**Status:** Approved L1-E semantic baseline

## Precedence

`Canonical AE mandatory semantics → Organization Engineering Baseline → Product/System Profile → effective implementation configuration → governed AE work`

## Product/System Profile may

- add stricter constraints;
- select/narrow scope-specific Capability Bindings;
- add product architecture/risk/classification context;
- specialize organization defaults;
- add product-specific evidence/Validation expectations;
- narrow provider choices.

## Product/System Profile may not silently

- weaken Canonical AE mandatory semantics;
- weaken mandatory organization policy;
- weaken mandatory security/governance controls;
- hide an applicable failed Capability Proof.

A legitimate exception must eventually be explicit, authorized, scoped, reasoned, versioned/provenanced, and reflected in effective configuration.

Detailed exception mechanics remain downstream.

## Effective configuration

The resolved combination of Canonical AE + exact OEB revision + exact Product/System Profile revision + applicable approved exceptions is normally a **derived projection [D]**, not another A1 entity.

## Revision history

A newer OEB/Profile revision does not retroactively rewrite prior work. Active-work reassessment occurs only through applicable explicit policy/effectivity semantics when later domains define them.
